# Codexterity v0.2.0 — release notes

**Released 2026-09-23.** This release keeps Codexterity working on Codex's September 2026 update.
Project version `0.2.0` (`package.json`, which the macOS builder also stamps into the app bundle).
Captain's Cabin's theme version stays `0.1.0`, deliberately: **no colour, font or hero changed**. The
goal was that the theme looks exactly as it did on 2026-08-05.

Codexterity is a non-destructive theming layer for OpenAI's Codex Desktop app. It reskins Codex at
runtime through the app's own official Electron APIs, and never modifies, patches or re-signs any
Codex file. One theme ships: **Captain's Cabin**, a deep-navy, brass and candlelight chart-room look
with a weathered-parchment light mode.

As in v0.1.0, every claim below is either **verified** (something was run and observed) or **built
but unverified** (it exists, and nobody has watched it work).

---

## Why this release exists

Codex `26.917` moved onto a new runtime that OpenAI calls **OWL** and reorganised its colour system.
With v0.1.0 on that Codex, the theme still loaded and was inserted without a single error, and then
**matched nothing**, so Codex rendered stock. Nothing was blocked: the injection mechanism, the
launcher, the package format and the installer all kept working unchanged. What broke was the
*vocabulary*:

- Codex's light/dark switch moved from the `.electron-dark` / `.electron-light` classes to a
  `data-theme` attribute.
- 60 of the 77 colour variables the theme overrides were renamed (`--color-X` → `--app-color-X`),
  and one disappeared.
- The theme is now inserted as a *user*-origin stylesheet, where only `!important` declarations win,
  so every declaration the theme writes is now `!important`.

v0.2.0 re-points the engine at the new names. Codex's ChatGPT **Chat** and **Work** areas now live
inside the app, and they are themed too. The full record is
[Plan 0004](../plans/0004-codex-owl-token-remap.md), and the measured map of the new names is
[`docs/research/owl-token-inventory.md`](../research/owl-token-inventory.md).

**v0.2.0 supports the new Codex only.** On a Codex older than `26.917` it shows stock. v0.1.0 is the
build for an older Codex, and it is not maintained (D-0004-3).

installer. The repository's `dist/` folder was moved aside during the launches, so none of them could
have read from the working tree.

| The injector really attached | `injector.log`: the package loaded from the install folder, `injected OK via insertCSS` on every window, and the five landmarks the screen could show reported `PRESENT` |

### Verified in the test instance only

**Codex updated again on release day, to `26.917.8451.0`**, after the owner's launches. The built
Captain's Cabin package was run against it in the isolated test instance: all eleven screens opened,
and the ground, sidebar, ink and brass painted the same values, confirmed on the captured pixels. No
owner launch has been made on `8451`, so its themed launch through the shortcut is not claimed here.

## Built but unverified

**The macOS package has never run on a Mac.** It is rebuilt for this release and carries version
`0.2.0`, and the build is exercised by the test suite. But no part of it (installing, launching,
theming, removing) has been observed on Apple hardware, and the `.dmg` step has never been run. That
is its finished state, not an open task (D-0001-16 as amended).

## Known and deliberate

- **The code colours inside Codex's diff view stay OpenAI's own.** The diff's background, font and
  added/removed line tints are themed. The syntax colours of the code text are not. That is an owner
  decision (D-0004-5), not an oversight.
- **Status colours are unproven.** Codex's error, warning and success banners and chips were not on
  any screen checked for this release. They are left at Codex's values and have not been seen themed.
- **Launching Codex from Codex's own icon gives stock Codex.** The theme attaches when Codex's
  process starts (D-0001-30).
- **Codexterity never checks your Codex version.** This update is exactly the case D-0001-31
  anticipated: the landmark report in `injector.log`, not a version check, is what surfaced the problem.

## Artifacts, and how to rebuild them

Build output is deliberately not committed (`dist/` and `*.ccskin` are gitignored), and this release
tags source, not binaries. All three commands were run against the tagged tree on 2026-09-23 and
produced the sizes shown.

```bash
node tools/pack-ccskin.js
node tools/build-windows-package.js
node packaging/macos/build-macos-package.js
```

| Command | Output | Size |
|---|---|---|
| `node tools/pack-ccskin.js` | `dist/captains-cabin.ccskin`, the theme package itself | 683,628 bytes |
| `node tools/build-windows-package.js` | `dist/Codexterity-Windows/`: `Install.ps1`, `Uninstall.ps1`, `README.txt`, `payload/`. Runs the packer first | 20 files, 1,026,753 bytes |
| `node packaging/macos/build-macos-package.js` | `dist/Codexterity-macOS/Codexterity.app` plus `install.sh` / `uninstall.sh` | 17 files, 954,358 bytes |

**Upgrading from v0.1.0:** run the new `Install.ps1`. It replaces the install folder, and with it the
injector and the theme package, then re-applies Captain's Cabin. Reinstall rather than only re-applying
the theme: re-applying keeps the v0.1.0 injector, whose diagnostics in `injector.log` still look for the
old names. Only the reinstalled combination is what was verified above.

**Why `theme.css`'s digest moved and `syntax.json`'s did not.** `theme.css` changed because every
selector and variable name in it moved to Codex's new names. No colour value changed: the palette is
generated from the same unchanged recipe, the audit is unchanged at 292/292, and the owner reviewed it
on sight. `syntax.json` encodes colours only, so it is
byte-identical to v0.1.0. `manifest.json` moved because it gained one optional landmark, for the fix
that keeps the update pill readable (D-0004-4). Its `verifiedAgainst` field still reads
`26.727.6591.0`: nothing reads it (D-0001-31), and it is not a statement about this release.

## What is not in this release

- **No new theme and no theme picker.** The authoring pipeline from
  [Plan 0003](../plans/0003-image-led-theme-authoring.md) produced a second, private theme that is not
  distributed. It was also re-verified on the new Codex.
- **No support for pre-OWL Codex** (D-0004-3).
- **No change to the injection mechanism, the package format or the loader.**
