# Codexterity v0.1.0 — release notes

**Released 2026-08-05.** First tagged release. Every measurement below was taken on 2026-08-04–05 —
the release session ran across midnight, so both dates appear and mean the same run. Project version `0.1.0`
(`package.json`), theme version `0.1.0` (Captain's Cabin) — both left as they stood; nothing was
bumped for the tag, and no token value changed.

Codexterity is a non-destructive theming layer for OpenAI's Codex Desktop app. It reskins Codex at
runtime through the app's own official Electron APIs, and never modifies, patches or re-signs any
Codex file. One theme ships: **Captain's Cabin** — a deep-navy, brass and candlelight chart-room
aesthetic, with a weathered-parchment light mode.

Every claim below is split into **verified** (something was run and observed) and **built but
unverified** (it exists, and nobody has watched it work). Nothing sits between the two.

---

## Verified on Windows

Verified on this machine — Windows 11 Pro 26200, Node v22.14.0 — against installed Codex
`OpenAI.Codex_26.727.6591.0_x64__2p2nqsd0c76g0` (version `26.727.6591.0`). Each item was observed in
the running app or on the real filesystem, **from the built package**, not from the working tree.

### Verified by simulation, not by waiting

**A Codex update that renamed every interface landmark would cost the app nothing visible.** With all
six landmark selectors deliberately broken, Codex stayed fully functional and fully themed, and the
log named each broken landmark individually with its selector (Plan 0002 M4). This is a simulation of
the failure mode, run because the installed Codex version cannot be moved on demand. **No real Codex
update has been survived yet** — that is a claim no run supports and it is not made here.

## Built but unverified

**The macOS package has never run on a Mac.** `packaging/macos/build-macos-package.js` produces
`dist/Codexterity-macOS/Codexterity.app` and the build itself is exercised by the test suite, but no
part of it — installing, launching, theming, or removing — has been observed on Apple hardware. That
is its finished state for this release, not an open task (D-0001-16 as amended: the ruling that macOS
is documented unverified and never blocks a release). `packaging/macos/README.md` says the same thing
to whoever tries it first, and says what to write down if it fails.

The final `.dmg` step (`packaging/macos/build-dmg.sh`) requires macOS and has never been run at all.

## Expected behaviour that looks like a bug and is not

- **Launching Codex from Codex's own icon gives stock, unthemed Codex.** The theme attaches at the
  moment Codex's process starts, so a Codex that Codexterity did not start is a plain Codex. Inherent,
  not a defect (D-0001-30 — the ruling that this is expected and is not to be designed around).
- **While themed Codex runs, the taskbar shows the running indicator under Codex's icon, not
  Codexterity's.** The Codexterity shortcut is a launcher for Codex, and deliberately does not present
  itself as a second application (D-0001-30).
- **Codexterity never checks your Codex version and never refuses to apply because of one.** The
  theme package declares a version range, and nothing enforces it, on purpose: blocking a working
  theme on a routine Store update would be the worse failure (D-0001-31 — the ruling that the range is
  declarative metadata and no version gate is to be built).

## Artifacts, and how to rebuild them

Build output is deliberately not committed — `dist/` and `*.ccskin` are gitignored, and this release
tags source, not binaries. All three commands below were run against the tagged tree on 2026-08-04
and produced the sizes shown.

```bash
node tools/pack-ccskin.js
node tools/build-windows-package.js
node packaging/macos/build-macos-package.js
```

| Command | Output | Size |
|---|---|---|
| `node tools/pack-ccskin.js` | `dist/captains-cabin.ccskin` — the theme package itself | 681,124 bytes |
| `node tools/build-windows-package.js` | `dist/Codexterity-Windows/` — `Install.ps1`, `Uninstall.ps1`, `README.txt`, `payload/`. Runs the packer first, so it needs no separate step | 20 files, 983,258 bytes |
| `node packaging/macos/build-macos-package.js` | `dist/Codexterity-macOS/Codexterity.app` plus `install.sh` / `uninstall.sh`. Runs on any platform; codesigning and the `.dmg` are macOS-only follow-ups | 17 files, 911,958 bytes |

To hand someone a Windows copy, send them the whole `dist/Codexterity-Windows` folder and point them
at `README.txt` inside it.

## What is not in this release

One theme, no theme picker, and no way to change the theme of a Codex window that is already open —
restarting Codex through the shortcut is how a theme change takes effect. Multi-theme authoring and
distribution is the next body of work and is explored, unapproved and unscheduled, in
[`docs/research/multi-theme-authoring-and-switching-exploration.md`](../research/multi-theme-authoring-and-switching-exploration.md).
